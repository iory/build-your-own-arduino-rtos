# 第6章: メモリ保護

MPU（Memory Protection Unit：アクセスしてよいメモリの範囲を CPU が見張る仕組み）を使ってタスク同士のメモリを守り、暴走を検出します。

:::{admonition} この章で分かること: アプリが落ちても、OS が落ちないのはなぜ？
:class: tip

PC では、アプリが 1 つ落ちても、OS やほかのアプリは動き続けます。
OS が、おかしなことをしたプログラムだけを終わらせているからです。

この章では、ゼロ除算や、存在しないアドレスへの書き込みで CPU が起こす例外
（フォールト）を OS が受け止めて、起こしたタスクだけを止めます。
ほかのタスクは何事もなかったように動き続けます。
:::

### 1. 続けて 5 回落とす

`d` を 5 回続けて送り、しばらく待ってから `p` でタスクの一覧を出します。

**予想:** `FAULT DETECTED` は何回出るでしょう。

:::{dropdown} 答え
**4 回しか出ません。** 5 回目も `Creating div-by-zero crash task...` とは表示されますが、
そのあとの `[Crash] Dividing by zero in 3 seconds...` が出ません。

```text
Creating div-by-zero crash task...
[Crash] Dividing by zero in 3 seconds...
Creating div-by-zero crash task...
[Crash] Dividing by zero in 3 seconds...
[Heartbeat] 1
Creating div-by-zero crash task...
[Crash] Dividing by zero in 3 seconds...
Creating div-by-zero crash task...
[Crash] Dividing by zero in 3 seconds...
Creating div-by-zero crash task...
[Heartbeat] 2
（FAULT DETECTED が 4 回）

ID  NAME           STATE
0   idle     READY
1   LED     BLOCKED
2   Heartbeat     BLOCKED
3   Shell     RUNNING
4   Crash_Div     TERMINATED
5   Crash_Div     TERMINATED
6   Crash_Div     TERMINATED
7   Crash_Div     TERMINATED
```

タスクを入れておく表 `g_tasks` は `MAX_TASKS` = 8 個ぶんしかありません。
起動時の 4 つ（idle・LED・Heartbeat・Shell）で半分を使い、残りの 4 つを
`Crash_Div` が埋めます。`TERMINATED` になったタスクの場所は再利用されないので、
5 回目の `os_create_task()` は -1 を返して何もしません。シェルは戻り値を
見ていないので、「作ります」とだけ言って、失敗に気づきません。

タスクが終わるたびに場所が減っていくので、この OS は、落ちたタスクを作り直し続けるような
使い方には向きません。
:::

### 2. ゼロ除算の見張りを外す

`src/os_fault.cpp` の `fault_init()` で、ゼロ除算を例外にする設定をコメントにします。

```diff
-    SCB->CCR |= SCB_CCR_DIV_0_TRP_Msk;
+    // SCB->CCR |= SCB_CCR_DIV_0_TRP_Msk;
```

**予想:** `d` を送ると、`100 / 0` はどうなるでしょう。

:::{dropdown} 答え
**`FAULT DETECTED` が出ません。** それなのに、`p` で見ると `Crash_Div` は
`TERMINATED` になっています。

```text
Creating div-by-zero crash task...
[Crash] Dividing by zero in 3 seconds...
[Heartbeat] 1
[Heartbeat] 2
[Heartbeat] 3

ID  NAME           STATE
0   idle     READY
1   LED     BLOCKED
2   Heartbeat     BLOCKED
3   Shell     RUNNING
4   Crash_Div     TERMINATED
```

Cortex-M の割り算命令は、この設定（`CCR.DIV_0_TRP`）が無いと、0 で割っても
例外を起こさず、答えを 0 にして先へ進みます
（[Arm の解説「Divide and Conquer」](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/divide-and-conquer)）。
`c` が 0 になったまま `task_crash_divzero()` は最後まで走って return し、
タスクが return したときの受け皿 `task_exit()` が `TERMINATED` にしています。

エラーを出さずに、間違った答えで先へ進んでしまうわけです。
`fault_init()` がわざわざこの設定を入れているのは、このためです。
:::
