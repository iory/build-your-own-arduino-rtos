# 第7章: LEDマトリクス可視化

UNO R4 WiFi 内蔵の LED マトリクスに OS の内部状態を表示します。

## LED マトリクスの配線

96 個の LED は、11 本の線（ROW0〜ROW10）の**チャーリープレクシング**で
つながっています。2 本の線の組ごとに向きが逆の LED が 2 個ついていて、
片方を HIGH・もう片方を LOW にすると 1 個だけが光ります。右上の表は、
回路図上の LED 番号とマトリクス上の位置の対応です。

付属の `Arduino_LED_Matrix` ライブラリは、10 kHz のタイマ割り込み 1 回ごとに
LED を 1 個ずつ順に点け替えています（96 個で 1 周するので、1 画面あたり
約 104 Hz）。
([`Arduino_LED_Matrix.h` L182](https://github.com/arduino/ArduinoCore-renesas/blob/1.5.1/libraries/Arduino_LED_Matrix/src/Arduino_LED_Matrix.h#L182)、
[L346–L349](https://github.com/arduino/ArduinoCore-renesas/blob/1.5.1/libraries/Arduino_LED_Matrix/src/Arduino_LED_Matrix.h#L346-L349)、
ArduinoCore-renesas 1.5.1)

## 実機での出力

Arduino UNO R4 WiFi の実機で実際に取得した出力です（macOS / Windows の
両方で同じ結果を確認しています）。手元の出力と見比べてください。

```text
ps

ID  NAME           STATE      CPU%
--  ----           -----      ----
0   idle           READY     50%
1   LED            BLOCKED   0%
2   Light          BLOCKED   0%
3   Heavy          READY     49%
4   Shell          RUNNING   0%
5   Display        READY     0%

> 
```

実機のマトリクスはこう動きます。

```{figure} ../_static/ch07_kill.gif
:name: fig-ch07-board
:width: 80%

実機の LED マトリクス。上半分が直近 1.2 秒の CPU 負荷で、0.1 秒ごとに左から順に 1 列ずつ書き換わります。下半分の右端 2 列はタスク 0〜3 の状態です。`kill 3` で `Heavy` を止めるとグラフが下がり、`exec 3` でまた上がります。（UNO R4 WiFi を Web カメラで撮影）
```

## 改良版: `07_led_matrix_v2`（書籍未掲載）

本書のコードの表示は、上半分の負荷の履歴が時間の順に並んでいないことと、
下半分がほとんど光らないことから、何を表しているのか読み取りにくいところが
あります。そこで表示を Linux の `htop` のような「**いまの値**」の横棒に
した改良版を
[`code/07_led_matrix_v2`](https://github.com/iory/build-your-own-arduino-rtos/tree/main/code/07_led_matrix_v2) に置きました。カーネルは本書と同じで、
変えたのは表示・シェル・タスクの中身だけです。

| 行 | 中身（どれも 12 個で 100%、0.5 秒ごとに更新） |
|---|---|
| 0–1 | CPU 全体の負荷（idle 以外） |
| 2 | 空き |
| 3–7 | LED / Light / Heavy / Shell / Display の CPU 使用率 |

シェルに足した `top` と打つと、マトリクスと同じ数字が 0.5 秒ごとに端末へ
描き直されます（もう一度 `top` で止まる。表示中も `kill 3` などを打てます）。
Heavy 以外に Light も CPU を使うようにしてあるので、行ごとの棒を足すと
CPU 全体の棒になるのが見えます。

```{raw} html
<video src="../_static/ch07_v2_top.mp4" poster="../_static/ch07_v2_top_poster.jpg"
       controls muted playsinline preload="metadata"
       style="width:100%; border-radius:8px;"
       aria-label="07_led_matrix_v2 の実機のマトリクスと、端末の top を並べた動画"></video>
```

実機（UNO R4 WiFi）の `top` の値は次のとおりです。

| 操作 | CPU 全体 | 目に見えること |
|---|---|---|
| 起動直後 | 約 60% | Light（16%）と Heavy（40%）の行に棒 |
| `kill 3` | 約 24% | Heavy の棒が消え、全体の棒が縮む |
| `kill 2` | 約 4% | 残るのは `top` を描いている Shell だけ |
| `exec 2` / `exec 3` | 元に戻る | |

```{note}
Heavy は眠らずに回り続けても 40〜50% しか取れません。本書のスケジューラは
idle も普通のタスクと同じ順番で回すので、idle と CPU を分け合うためです。
```

~~~{admonition} コラム: `top` と `htop`
:class: tip

Linux には、動いているプロセスごとの CPU 使用率を一覧する `top`（procps-ng）と、
それを見やすくした `htop` があります。v2 のマトリクスとシェルの `top` は、
この 2 つを真似たものです。

**見ているもの。** `htop` の画面上部の CPU メーターは、CPU 時間を種類
（nice・user・system など）ごとに色分けして積み上げた横棒です
（[htop(1) の METERS](https://github.com/htop-dev/htop/blob/1daf6d9312d13f6edb4593340b9c3f65a7eadad4/htop.1.in)）。その下の一覧の `%CPU` は、
「前回画面を描いてから今回までの経過時間のうち、そのプロセスが使った割合」です
（[top(1) の %CPU](https://man7.org/linux/man-pages/man1/top.1.html)）。v2 では行 0–1 が CPU メーター、行 3–7 が一覧に
あたります。

**更新の間隔。** `htop` は既定で 1.5 秒ごとに描き直します（`-d` は 0.1 秒単位で、
既定値は 15。[Settings.h](https://github.com/htop-dev/htop/blob/1daf6d9312d13f6edb4593340b9c3f65a7eadad4/Settings.h#L21)）。procps-ng の `top` も既定は 1.5 秒で、
元の設定でビルドした場合は 3 秒です（[top.h](https://gitlab.com/procps-ng/procps/-/blob/55b7d01d2c6006362b1d221a41594c40b6d77640/src/top/top.h#L124-129)）。v2 は 0.5 秒です。

**CPU 時間の数え方。** Linux は基本的に、タイマ割り込み（tick）のたびに
「そのとき走っていたタスク」へ 1 tick ぶんの CPU 時間を足していきます
（[`account_process_tick()`](https://github.com/torvalds/linux/blob/f0100363d8c374bd8e9ea7c9ba02744f0b802ca4/kernel/sched/cputime.c#L683-L712)）。その合計が `/proc/stat`
（[proc_stat(5)](https://man7.org/linux/man-pages/man5/proc_stat.5.html)）などに出ていて、`top` は 2 回読んだ差分から
割合を出します。本書の OS も、SysTick 割り込みのたびに走っていたタスクへ 10 ms
を足していて（`os_kernel.cpp` の `SysTick_Handler`）、考え方は同じです。
v2 はこの値を 0.5 秒ごとに 2 回読んで差を取っています。

tick で数える方式は、tick と tick の間に終わってしまう短い仕事を取りこぼします。
LED タスクが 0% に見えるのはこのためです（Linux でも、設定によっては tick 以外の
方法で数えます）。

**止める。** `top` では `k`、`htop` では `F9` か `k` で、選んだプロセスにシグナルを
送って止めます（[top(1)](https://man7.org/linux/man-pages/man1/top.1.html)、[htop(1)](https://github.com/htop-dev/htop/blob/1daf6d9312d13f6edb4593340b9c3f65a7eadad4/htop.1.in)）。本書のシェルの
`kill N` はタスクを一時停止（suspend）するだけなので、`exec N` で再開できます。
~~~
