# 2 段モデル: 段 B の有無の比較結果

`joint` (段 A + 関節ごとの残差 段 B) と `baseline` (段 B なし、段 A 単体) を、同じ環境・同じ報酬・同じ学習量で学習して比べた結果です。
実装は [TWO_STAGE.md](TWO_STAGE.md)、実行は `compare_two_stage.sh` です。
**各 run を 2300 iteration 学習した時点 (第 1 回) と、さらに 2300 iteration 延長した時点 (4600 iteration、第 2 回) の両方を載せます。** 第 1 回の結論は、延長すると覆りました (1 節の末尾と 4.3 節)。

## 1. 結論 (4600 iteration、各モード 3 seed)

| 指標 | joint (A+B) | baseline (A のみ) |
|---|---|---|
| 最終平均報酬 (最後の 100 iteration、3 seed の平均 ± 標準偏差) | 78.7 ± 12.6 | 71.5 ± 8.2 |
| エピソード長が上限 (1000) 近くに達した seed | 3 / 3 | 3 / 3 |
| 評価で全ロボットが転倒した条件 (3 seed × 4 コマンド × DR なし/あり = 24) | 0 / 24 | 0 / 24 |
| 評価の並進誤差 \|vx − 指令\| (m/s) | **0.0043** | 0.0098 |
| 評価の旋回誤差 \|wz − 指令\| (rad/s) | **0.086** | 0.122 |
| 報酬の移動平均が初めて 20 を超えた iteration (3 seed / 中央値) | **462 / 785 / 2043 (785)** | 494 / 2729 / 3874 (2729) |

1. **十分に長く学習すれば、`baseline` (段 B なし) も、`joint` と同じように歩けるようになります。** 4600 iteration で、両モードとも 3 seed すべてで、エピソード長が 991〜1000、評価の 24 条件すべてで転倒ゼロでした。
2. **最終的な報酬に、明確な差はありません。** 78.7 ± 12.6 と 71.5 ± 8.2 で、差 (7.2) は標準偏差と同程度か小さく、3 seed では有意とは言えません。
3. **離陸 (報酬が上がり始める時点) は、`joint` のほうが早い傾向があります。** 報酬の移動平均が 20 を超えた iteration の中央値は、`joint` が 785、`baseline` が 2729 です。`baseline` の seed 1 と 3 は、2300 iteration まで報酬 1 前後で停滞し、それぞれ 2729 と 3874 iteration でようやく離陸しました。ただし `joint` の seed 2 も、離陸に 2043 iteration かかっており、3 seed で見た傾向です。
4. **評価の追従は、`joint` がわずかに良好です** (並進誤差 0.0043 vs 0.0098 m/s、旋回誤差 0.086 vs 0.122 rad/s)。ただし、旋回の実測は seed によるばらつきが大きく (4.5 節)、この差を段 B の効果と断定できません。
5. **旋回は、どちらのモードでも指令の半分以下です** (指令 0.3 rad/s に対して、実測の平均は `joint` が 0.128、`baseline` が 0.082)。

**第 1 回 (2300 iteration) との違い**: 第 1 回では、`joint` が 24 条件で転倒ゼロ、`baseline` が 12 / 24 条件で全転倒でした (4.3 節)。この差は、`baseline` の seed 1 と 3 の学習が、まだ離陸していなかったためで、モデルの能力の差ではありませんでした。

## 5. 考察

数字は 4.1〜4.5 から引いています。

1. **学習の成否** (4.1)
   - 4600 iteration で、両モードとも 6 本すべてが、エピソード長 991〜1000、fell_over はほぼ 0 に達しました。
   - `baseline` の seed 1 と 3 は、2300 iteration まで報酬が 1 付近で停滞していましたが、それぞれ約 2700 と約 3900 iteration で突然離陸し、81.5 と 71.6 まで上がりました。長い停滞の後にも離陸する可能性があるので、「停滞している = 学習できない」とは言えません。
2. **最終的な報酬** (4.1)
   - `joint` は 78.7 ± 12.6、`baseline` は 71.5 ± 8.2 です。差は小さく、有意とは言えません。
   - 最良の seed は、`joint` seed 3 (91.3) が `baseline` seed 1 (81.5) を上回りますが、これも 1 seed ずつの比較です。
   - `joint` seed 2 と `baseline` seed 2 は、どちらも報酬 61.4 と、他の run より低いです。`joint` seed 2 は、並進の追従報酬 (track_lin) が 0.014 と他 (0.038〜0.088) より小さい一方、旋回は最もよく追従します (4.5 節)。`baseline` seed 2 は、`0.06,0` で止まったままです。
3. **離陸の早さ** (4.1)
   - 報酬の移動平均が 20 を超えた iteration は、`joint` が 462、785、2043 (中央値 785)、`baseline` が 494、2729、3874 (中央値 2729) です。50 を超えた iteration は、`joint` が 934、1090、2777、`baseline` が 1449、2964、4168 です。
   - `joint` のほうが早く離陸する傾向はありますが、`joint` の seed 2 も遅く、各 3 seed の範囲での観察です。
4. **評価での並進追従** (4.2, 4.4)
   - `joint` が 0.0043 m/s、`baseline` が 0.0098 m/s です。`baseline` の誤差は、seed 2 が `0.06,0` で止まっていること (vx 0.000) が効いています。
5. **旋回追従** (4.4, 4.5)
   - 指令 0.3 rad/s に対して、`joint` は平均 +0.128、`baseline` は +0.082 で、どちらも不十分です。
   - seed によるばらつきが大きく、`joint` は +0.036〜+0.253、`baseline` は +0.055〜+0.109 です。`joint` の最良は seed 2 (+0.253 / +0.219) で、最も報酬の高い seed 3 (+0.124 / +0.106) や seed 1 (+0.036 / +0.032) より旋回が良いです。**報酬が高いことと、旋回追従の良さは一致していません。**
6. **姿勢と歩容** (4.4)
   - roll RMS は、`joint` が 1.8〜3.3°、`baseline` が 0.9〜5.0° です。pitch RMS は、`joint` が 2.8〜7.2° (旋回指令 0, 0.3 で最大)、`baseline` が 2.7〜4.8° です。
   - `baseline` の seed 2 は、roll が 7〜11° と大きく (`0.12,0` で 10.9°)、他の run より姿勢が不安定です。

## 6. 制限と、まだ分かっていないこと

- **seed 数が少ない (各 3)。** 最終報酬の差 (7.2) は、標準偏差と同程度か小さいです。離陸の早さの差も、3 seed の中央値の比較です。結論を固めるには、seed を増やす (例 各 10) 必要があります。
- **まだ収束しきっていない run があります。** `baseline` seed 3 は、離陸 (約 3900 iteration) の直後で、4600 iteration の報酬 71.6 はまだ上昇中です (報酬曲線の末尾 6→25→46→62→70)。もっと回すと、`baseline` の最終報酬は上がる可能性があります。
- **旋回の追従が弱い原因は特定していません。** 報酬のバランス、学習量、遅延 0 の環境の影響などが考えられますが、確認していません。
- **学習の失敗や停滞が、モデルの構造のせいか、ハイパーパラメータ (`init_std`=1.0、学習率、KL 目標など) のせいかは切り分けていません。** 両モードで同じ値を使っています。
- **比較したのは「段 B の有無」だけです。** 従来の方策 (遅延 4〜7、3 フレーム履歴の現行モデル) との比較、`frozen` (既存方策への後付け) の効果は未検証です。
- 評価は 1 つの評価 seed (0) と 4 コマンドです。旋回の指令の大きさを変えた評価、後退や他の指令の組み合わせの評価はしていません。
- **学習は、ローカルとリモートの 2 台で行っています。** 速度は同じですが、浮動小数点の結果が完全に同じとは限りません。
- 実機の遅れ (サーボ内部約 23 ms) は、この sim では遅延 0 にしています。実機への適用性は、この結果からは言えません。

## 7. 再現

```
sh compare_two_stage.sh            # 第 1 回: 6 本の学習 (2300 iteration) と評価、2 台の GPU
sh compare_two_stage.sh extend     # 第 2 回: 全 6 本を +2300 iteration 延長 (--resume) して再評価
sh compare_two_stage.sh status
sh compare_two_stage.sh fetch      # リモートの results/logs を取り込む
```

- 生データ: `results/<mode>_s<seed>.txt` (第 1 回の評価)、`results/<mode>_s<seed>_ext.txt` (延長後の評価)、`.train.log` (学習ログ)。
- チェックポイント・tensorboard: `logs/rsl_rl/arduino_quad_velocity/*_<mode>_s<seed>[_ext]/`。
